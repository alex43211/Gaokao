一、我们是谁

本站由一位高校教师发起，联合有高考与就业一线经验的朋友共同维护，是一个非官方、非营利的公益工具站。 团队成员背景覆盖信息技术、经济与数据、重工/机械/汽车行业、医疗与精神心理方向， 因此内容上尽量做到「既讲得清专业，也讲得明行业」。

我们与教育部、各省教育考试院、任何高校及任何商业机构都没有隶属或合作关系，也不代表任何官方口径。

二、为什么要做

高考志愿是多数普通家庭孩子人生的第一次重大决策，但现实是：

  • 信息不对称。官方计划、一分一段表、院校章程分散在几十个网站里，家长看不懂、找不全。
  • 付费门槛高。市面上的志愿填报服务动辄数千元，普通家庭负担不起。
  • 重分数轻方向。很多人把「能上什么学校」当终点，忽略了「这个专业四年后能不能找到工作」。

所以我们希望做一个不收费、看得懂、讲就业的辅助工具：把「专业、院校、城市、就业」放到同一张桌子上做决策。

五、发展路线图

阶段一（当前）· 把查询类功能做扎实

  • 教育部名单、专业目录、院校标签的准确性与可核验性；
  • 网页端体验打磨：搜索优先、移动端适配、无障碍与键盘操作；
  • 账号与留言板以「前端体验版」形态验证交互，不引入服务器成本。

阶段二· 引入后端，让数据可沉淀

  • 接入云数据库与登录鉴权，账号、方案、留言跨设备同步；
  • 留言分类转为工单：按「就业 / 专业选择 / 行情分析」分派给对应方向的成员答复并公开沉淀；
  • 接入真实数据源（省考试院一分一段表、院校投档线），逐步替换演示数据。

阶段三· 移动端与内容生态

  • 移动端形态按第六节的评估结论推进；
  • 开放行业供稿：不同行业的从业者贡献「这个专业毕业后到底在做什么」的一手内容；
  • 建立内容审核与纠错机制，接受公众对数据错误的反馈。

六、APP 化可行性分析

结论先说：现阶段不建议直接做原生 APP，推荐先走 PWA 路线，等功能与用户量验证后再评估小程序或原生。 理由如下。

路线成本与门槛优点缺点结论
PWA
（可安装的网页）		 低。现有站点加 manifest 与 Service Worker 即可 零上架审核、零分发成本；手机可「添加到主屏幕」，有独立图标与离线缓存 iOS 体验略受限；无法上架应用商店 强烈推荐，先做这个
微信小程序 中。需企业主体、备案与类目资质；教育类内容通常需相应资质审核 家长触达路径最短，分享传播最顺；无需安装 需后端配合，不能直接复用现有静态站；审核与资质周期长 用户量与内容储备起来后再做
混合壳套壳
（网页包一层原生外壳）		 中高。需 Android/iOS 双端打包、签名与上架 可上应用商店，短期成本低于纯原生 体验与网页差异不大，却引入上架与合规负担 性价比低，暂不考虑
纯原生双端 高。需双端开发、软著、ICP 备案、应用商店上架与持续维护 体验最好，可用推送等原生能力 成本与维护压力最大；本阶段收益不匹配 暂不考虑

如果将来要做 APP，必须先解决的问题

  1. 主体与资质。应用商店上架通常需要企业主体、软件著作权、ICP 备案；教育类内容可能另需资质文件。
  2. 后端与数据合规。用户数据上云后，需要隐私政策、数据最小化收集与安全保护措施。
  3. 内容责任。志愿建议类内容需明确免责边界，避免被理解为「录取承诺」。
  4. 持续维护。APP 的版本更新、兼容性与客服成本远高于网页，须有稳定投入。

在这些条件具备之前，把网页体验做好、把数据做准的收益，明显高于赶做 APP。

八、如何参与

  • 提意见与纠错：在 留言板 对应分类下留言，或使用「AI 志愿填报」页面的助手反馈入口。
  • 行业供稿：如果你是某个行业的从业者，愿意写一篇「这个专业毕业后到底在做什么」，非常欢迎——这正是本站最缺的内容。
  • 数据协助：如你手上有官方发布的一分一段表、招生计划等公开资料，欢迎提供线索，我们负责整理与结构化。
  • 分享传播：把本站转给需要的家长，是最省力也最有效的支持。
